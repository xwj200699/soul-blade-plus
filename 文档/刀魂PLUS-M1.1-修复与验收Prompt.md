## P0：修复 LOCAL VS 的 P2 选角阻断

### 已发现的问题

当前选角逻辑会在 P1 确认后进入：

```js
s.phase = 'char2'
```

但现有 `UI.drawSelect` 只在 `char` 或 `vs` 状态下进入相关绘制逻辑，`char2` 没有被纳入选角界面绘制条件。

虽然后续包装代码可能对 `_drawCharGrid` 增加了 `char2` 标签或光标处理，但如果 `_drawCharGrid` 在 `char2` 阶段根本没有被调用，玩家仍然看不到 P2 角色列表。

### 修改要求

- 将 `char2` 作为正式选角阶段处理，而不是依靠零散 wrapper 补丁。
- P1 确认角色后，界面必须清晰切换为 P2 选角。
- P2 选角阶段必须显示：
  - 完整角色列表；
  - 当前 P2 光标；
  - 已由 P1 选中的角色；
  - 明确的“P2 SELECT”或等价提示；
  - P2 的方向键与确认/返回按键提示。
- 允许 P1、P2 选择相同角色，除非原游戏规则明确禁止；如果禁止，必须给出可见反馈。
- P2 确认后才进入 VS 页面或战斗。
- P2 返回时，应正确回到 P1 选角或模式菜单，不得卡死。
- 不要通过透明、不可见但仍可操作的方式规避绘制问题。

### 验收标准

- 使用肉眼可以完成：标题页 → LOCAL VS → P1 选角 → P2 选角 → VS → 战斗。
- P2 选角阶段的角色列表、光标、说明文字均可见。
- 连续进入和退出 LOCAL VS 三次，不出现状态残留、黑屏或输入失效。

## P0：统一角色尺寸、锚点和碰撞盒

### 已发现的问题

当前原有三名角色的屏幕显示高度大约为 136–151px，而新增角色的估算显示高度约为：

- 悟空：约 243px；
- 后羿：约 227px；
- 安琪拉：约 221px。

新增三名角色约为原角色的 1.5–1.75 倍。同时现有 `bodyBox()` 仍可能使用固定约 148px 的高度，造成角色图像与受击区域不一致。

这会产生以下问题：

- 六名角色站在同一场景中比例不统一；
- 新角色头部或上半身可能处于碰撞盒之外；
- 攻击看似命中但没有判定，或没有接触却发生判定；
- 跳跃、蹲伏和倒地时锚点发生明显漂移。

### 修改要求

1. 逐个测量六名角色 Idle、Walk、Attack、Crouch、Jump、Hit、KO 动画中的有效像素边界。
2. 将六名角色正常站立时的屏幕可见高度统一到约 **140–155px**。
3. 不要只修改一个全局 scale：
   - 检查各动画帧的底部落脚点；
   - 统一脚底锚点；
   - 避免动画切换时角色上下跳动；
   - 检查朝向翻转后的水平偏移。
4. 将受击盒、攻击盒与角色缩放结果同步：
   - 受击盒应覆盖躯干和主要头部区域；
   - 蹲伏时降低受击盒高度；
   - 跳跃时跟随角色实际位置；
   - 长兵器、箭矢和魔法特效不能直接等同于角色身体盒。
5. 如果继续使用配置表，请为每名角色提供可维护的：
   - `renderScale`
   - `anchorX`
   - `anchorY`
   - `bodyBox`
   - 各招式 `hitBox`
6. 不得通过裁掉角色头部、隐藏超出部分等方式伪装尺寸统一。

### 验收标准

- 六名角色并排预览时，正常站姿高度差不超过约 10%。
- 每名角色的脚底稳定落在同一地面基准线上。
- Idle、Walk、Crouch、Jump、Attack、Hit、KO 切换时没有明显瞬移。
- 至少对六名角色分别进行一次近身攻击、远程攻击、蹲伏受击、跳跃受击测试。
- 可视攻击与实际命中基本一致，不出现明显“打空气”或“穿模命中”。

## P1：修复 LOCAL VS 的模式状态与 HUD

### 已发现的问题

`G.p2IsAI` 可能一直保持 `true`。原 HUD 会据此绘制 `CPU`，M1 的追加逻辑又可能在 LOCAL VS 中绘制 `P2`，造成同一位置同时出现 `CPU` 和 `P2`。

### 修改要求

- 将模式状态集中管理，不要通过多个 wrapper 重复补画标签。
- 进入不同模式时明确设置：
  - `VS CPU`：P2 为 AI，HUD 显示 `CPU` 或 AI 难度；
  - `LOCAL VS`：P2 为真人，HUD 只显示 `P2`；
  - `TRAINING`：显示训练模式对应状态。
- 退出战斗回到标题页时重置模式临时状态。
- 再次进入另一模式时，不得继承上一次的 AI、输入或 HUD 状态。
- 如果存在 `isAI`、`p2IsAI`、`gameMode` 等重复状态，尽量收敛为单一可信来源。

### 验收标准

- LOCAL VS 不出现 `CPU` 标签。
- VS CPU 不出现 `P2` 真人提示。
- 三个模式来回切换后，HUD 和实际控制方式始终一致。

## P1：清理 VS 页面的重复绘制

### 已发现的问题

原 `_drawVs` 可能先绘制实时角色 Sprite，M1 wrapper 随后又绘制角色肖像，形成双重人物、轮廓叠加或构图拥挤。

### 修改要求

- 检查 VS 页面完整绘制链，不要仅检查最后一层 wrapper。
- 为 VS 页面选择一种明确方案：
  - 方案 A：以角色肖像为主；
  - 方案 B：以动态 Sprite 为主；
  - 方案 C：肖像与 Sprite 分区呈现，但不能重叠。
- 推荐优先使用左右角色肖像、中间 VS 标识的稳定构图。
- 六名角色在 VS 页面必须使用一致的裁切比例、边距和视觉面积。
- 如果肖像素材质量不足，可以暂时使用经过统一构图的角色半身 Sprite，但不能让新旧角色使用完全不同的展示规则。

### 验收标准

- VS 页面每侧只存在一个明确的角色主体。
- 人物、名字、VS 标志、模式说明之间不重叠。
- 任意两名角色组合都能保持相同排版结构。

## P1：有限度改善后三名角色的美术一致性

### 当前判断

悟空、后羿、安琪拉的辨识度相比旧版已有提高，但仍更接近程序化像素人偶，与前三名传统像素格斗角色在细节、轮廓、光影和动作张力上存在差距。

本轮不要求彻底重画所有动画，但要解决最影响观感的部分。

### 修改要求

- 优先优化：
  1. 选角肖像；
  2. VS 肖像；
  3. Idle；
  4. 每名角色最常用的普通攻击；
  5. 必杀起手与命中关键帧。
- 增强角色轮廓差异：
  - 悟空：猴形面部、金红甲胄、长棍轮廓和灵活重心；
  - 后羿：弓的尺寸、拉弓姿态、东方神射手甲胄轮廓；
  - 安琪拉：双马尾、红色服装、魔法书或火焰媒介、轻快法师姿态。
- 增加关键动作的预备、命中和收招差异，避免只平移手臂或轻微改变局部像素。
- 保持原创或泛化设计，不直接复制商业游戏原始素材。
- 新旧角色必须保持同一像素密度、描边强度、受光方向和阴影层级。

### 验收标准

- 在不显示角色名字时，仍能通过轮廓区分后三名角色。
- 新角色肖像不再像默认人偶模板。
- 普通攻击和必杀至少具备清楚的预备—释放—收招节奏。
- 优化后不能重新引入尺寸和锚点错位。
